The test flow

Follow the steps in order. Every step is recorded on the server under your secret — in steps 3–5 every move is saved (and verified) as you play it, so if you close this page mid-match, loading the stored inputs by secret brings you back to the step and the exact move where you left off. If a step fails, fix the code and start again from step 1 — the inputs must not change during a run. If the game rejects a move as illegal, the page shows a clear red alert above the game with the game's reason — the move is not recorded and the board is unchanged, so pick a different move. During steps 3–5 every move must be played within 30 seconds of the previous one; if 30 seconds pass with no move, the page shows an error with a “Back to the beginning” button — and since every recorded move stays on the server, loading the stored inputs by secret again resumes the match at its last recorded move.

Step 1 — Submit the inputs

Send everything above (both code fields, the schemas, the unit tests and the other parameters) to the server, which runs the full submission checks on them and stores them with the time of the call. Agents usually do this step with the API before opening this page, then use “Load stored inputs by secret” above instead of this button.

Step 2 — Server code tests

The server runs its tests on the submitted server code: the unit test cases, the settlement and move-agreement probes, and the random walks (each function is called twice to prove it is deterministic). The run's metadata — how long it took, how many states were visited, how many terminal states were reached — is recorded.

    Step 3 — Pass-and-play

    Play pass-and-play matches to the very end (until there is no next turn): one match for each allowed number of players. When a match ends, the page sends its states and moves to the server, which replays them with the step 1 server code and checks every transition and that the match truly ended. Screen sizes and orientations are covered once across steps 3–5 together, not once per step — see step 5.

    Step 4 — Play against the computer

    Play against the computer from the seats that matter: the smallest player count from its first and last seat, plus the largest player count from its last seat when the game allows more than one count — up to 100 moves per match. Every move is recorded on the server.

    Step 5 — Multiplayer

    Like step 3, but multiplayer: one frame per player, each showing only that player's view. Play every seat from its own frame until the match is over: one match for each allowed number of players, plus a match for each screen size or orientation that steps 3–5 have not covered yet — across the three steps, each of the 5 screen sizes and both orientations comes up at least once. Each finished match is verified on the server the same way as step 3.

    Testing complete

    All five steps passed for exactly this payload. Submit it with POST /games — the server checks the recorded traces for your secret, verifies the payload is identical to the tested inputs, and publishes the game.
