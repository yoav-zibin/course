# Public game state

`all_state_public` is true when players share all gameplay information throughout
the game. Public dice games such as Backgammon and Pig remain public: an outcome
that will be generated by a future random roll is not existing hidden state.
Private hands, secret identities, face-down cards, and an already shuffled deck
or bag whose order is concealed make the flag false. Differences in legal-action
affordances between viewers do not make an otherwise public board private.

Pass-and-play skips the device handoff for games explicitly declaring true.
Missing metadata defaults to false so older packages preserve their handoff.
The flag is versioned with the rules. Existing matches pinned to older downloaded
packages keep their original behavior; a new local match from the refreshed game
uses its reviewed classification. Historical rules and saved moves are preserved.

The 21 checked-in declarative submissions explicitly classify all games. Public:
Backgammon, Checkers, Chess, Connect Four, Domineering, four-player Chess, Gomoku,
Hex, Mancala, Nim, Pig, Quoridor, Reversi, and Tic-tac-toe. Hidden: Battleship,
Crazy Eights, Go Fish, Guess Who, Hearts, Memory, and Spades. The generators retain
these classifications, as do bundled Tic-tac-toe and the native Connect Four
fixture.

The production catalog was also reviewed on November 19, 2026. The bounded
[manifest](../games/public-state-review.json) records all 149 published declarative
games, their reviewed versions and rule-source hashes, the chosen Boolean, and
the reason for it: 78 public and 71 hidden. These classifications describe the
implemented rules and filtered views, including concealed draw piles in games
whose current board is otherwise public.

Changing checked-in submissions does not update games already in the database.
After deploying the API, apply this review through the ordinary metadata-only
`PATCH /games/{id}` endpoint:

```sh
python -m game_platform.tools.publish_public_state_flags
python -m game_platform.tools.publish_public_state_flags --apply \
  --secret-file /private/path/to/master-password \
  --report /private/path/to/public-state-publication.json
```

The first command is read-only. The second checks every reviewed game before
the first write, then rechecks the exact source and version immediately before
each update. An intervening source or version edit requiring a write stops the
run for review. Updates send only the Boolean and the authorization secret;
rules, presentation and validation artifacts are omitted. Already-correct flags
are accepted on reruns, including the new versions created by a prior run. The
secret stays in its private file and is never included in output or reports.

When concurrent updates to `main` keep superseding automatic deployments, the
`Deploy tested main revision` workflow accepts a completed, successful push-to-main
CI/CD run ID. It verifies the required checks and artifact provenance, deploys
that exact source and web build, preserves private configuration, and restores
the previous release if verification fails. It refuses to replace a newer
production revision. Trigger it with `gh workflow run deploy-tested.yml --ref main
-f ci_run_id=RUN_ID`, then apply the reviewed flags after deployment succeeds.
